# ssh33 实测：先加入对象记忆，CLIP 暂不默认启用

2026-09-27，RTX 4060 Laptop 8 GB，5 个场景 × 25 个固定视角，A/B/C 各测两轮，共 30 次运行。使用真实 Qwen3-VL 2B NF4 推理，C 另真实执行按需 OpenCLIP。正式 pipeline 没有改动。

**B 在这批输入上保持输出完全一致，将 SAM3 之后的融合与命名阶段耗时减少 28.3%。没有测出质量提升。C 加入 CLIP 后没有改变输出，额外成本基本抵消了 B 的提速。**

## 主要结果

下面使用第二轮，文件缓存已热，但每次都新建进程、重新加载模型。耗时包含融合、选图、模型启动、推理、导出和回填，也包含 B/C 先等待融合造成的并行损失。

| 方案 | 5 场景合计耗时 | VLM 调用 | 命名输出与 A 一致 |
|---|---:|---:|---:|
| A：全部裁剪图逐张识别 | 88.00 秒 | 570 | 基准 |
| B：对象分组＋代表视角＋冲突时补看 | **63.11 秒** | **130** | **52/52 个物体** |
| C：B＋按需 CLIP 关联复核 | 87.33 秒 | 130 | 52/52 个物体 |

- B 减少 **440 次调用，77.2%**；实际阶段耗时减少 **24.89 秒，28.3%**。
- C 比 B 多用 **24.21 秒，38.4%**；比 A 仅少 0.67 秒。这种微小差别不能当作稳定的加速收益。
- 两轮中，各方案每张实际推理裁剪图的标签、最终物体名称都可重复。A/B/C 均为 **27 个有名称、25 个未知**。
- 30 次运行的 XYZ、semantic、instance、confidence 全部一致；前三个场景另与此前固定融合基线一致。

**这里的 28.3% 仅适用于 SAM3 之后的处理阶段。SLAM 和 SAM3 使用固定缓存，没有重跑；完整 RGB-D pipeline 的总加速比例尚未测量。**

## 调用到底省在哪里

570 张候选裁剪图中，215 张不能通过原有的几何归属与至少两帧证据条件形成有效命名，B 跳过它们。在剩余 355 张图里，对象级代表视角与证据复用进一步减少 225 次，最后实际执行 130 次。

B 首先选择最多 3 个不同原始帧；如果得不到至少两帧支持的严格多数，再识别该物体其余有效裁剪图。本轮 4 个物体触发了补看。没有把复用的名称伪装成新的多帧证据，也没有跨运行读取历史 VLM 答案。

因此收益来自“过滤无法回填的请求”和“减少同一物体的重复识别”两项，不能全归因于新增视觉模型。

## 质量结论及一个需要继续排查的错误

输出一致说明 **这批固定输入上没有引入名称、语义标签或实例归属退化**，同时原有错误和未知对象也保持原状。

预测封存后，按预先固定的几何支持和 GT 纯度条件，只有 **8 个前景实例**进入严格名称核对：三组都是 6 个名称与 GT 一致、1 个名称冲突、1 个未知。scene0050_00 与 scene0000_00 没有实例达到这一严格诊断条件，不能据此评价它们的开放词汇命名准确率。这个小样本也不能作为全场景准确率。

其中 scene0011_00 的实例 5，GT 点投影的主导类别是 `table`，SAM3 及保留的 semantic_id 是 `trash bin`，三个代表裁剪图的 VLM 输出都是 `gravestone`。直接查看其中一张裁剪图后，不能简单把这条诊断解释为“VLM 把一张清楚的桌子认成墓碑”：这里同时存在 **图像类别、SAM3 类别和 3D GT 对应关系的冲突**。应继续检查带上下文的图像与投影归属，不能只增加相同裁剪图的调用次数。

这也解释了当前 C 的局限：上述裁剪在预测地图里的几何归属比例为 0.975～1.0，未触发几何歧义检查；预测地图内部的高一致性并不等于外部 GT 正确。

## 为什么 C 没有帮助

本轮 C 只需要复核 7 张有几何歧义且有独立原型的图像，共新编码 19 张图。**撤回关联 0 次、改变名称 0 个。** 图像编码本身约半秒到一秒，加载 ViT-H-14 及进程启动每个触发场景额外约 8 秒。

VLM 进程的 PyTorch 峰值 reserved 约 1.60 GiB，A/B 基本相同；CLIP 进程达到约 **3.84 GiB**。第二轮 VLM 单进程峰值 RSS 约 5.00 GiB，CLIP 约 **8.03 GiB**。这些不是包含桌面、父进程和其他阶段的整机峰值。本方案减少调用，并没有显著降低 VLM 权重的常驻内存；加 CLIP 反而增加了阶段资源需求。

## 接入建议

1. **优先继续 B**：作为可关闭的实验选项，先做完整录制的端到端验收。对象记忆保留原始帧、裁剪哈希、几何归属与真实推理证据，名称不反向覆盖已验证的点云标签。
2. **C 保持关闭**：本轮没有证据支持把 ViT-H-14 默认加入。若后续复用其特征做查询或实例关联，应把复用收益和模型加载成本重新实测。
3. **质量改进的下一步**：为 SAM3、VLM 与跨视角证据之间的类别冲突设计复核，尝试带上下文的裁剪与明确的回退条件。先查清 scene0011_00 的对应关系，再安排独立验证；本轮不按 GT 调参。

本次只是隔离测试实现，没有合入、推送或替换正式 pipeline，也没有实现跨运行持久缓存。完整方法与限制见同目录 `object-memory-method.md`。
