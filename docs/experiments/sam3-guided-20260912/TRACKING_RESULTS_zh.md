# SAM3 视频跟踪与视觉提示验证

结论：视频跟踪对部分跨帧重复、闪烁有帮助，但不能统一替代独立图像预测；Orbbec 蓝色设备的单帧诊断则说明，描述性提示可以唤起现有 SAM3 已有的分割能力。当前未把这些探针替换为完整地图默认方案。

## 实际运行范围

在 ssh44 RTX 5070 Ti 上使用原有 SAM3 官方源码和同一份严格校验的 checkpoint，完成 102 个冻结 RGB-D 观测的配对图像/视频推理：Orbbec 窗帘 48 帧、线缆卷盘 16 帧，ScanNet0030 椅子 32 帧，以及 3RScan 保存的 6 帧。图像与视频支路使用完全相同的 RGB、深度、位姿、地图、提示词和 0.5 输出门槛。它们都是单概念探针，不是完整分类表推理，不是全场景 Any3DIS 复现。

额外完成线缆卷盘首帧正框/正负框实验及首帧正框视频传播，并完成蓝色设备 frame4811 的四个固定提示对照。所有人工框都在相应实验前按原始 RGB 固定；没有读取 GT 或根据结果修改提示词、框、阈值。

## 主要结果

| 片段 | 单帧图像 → 视频 | 解释 |
|---|---|---|
| Orbbec 窗帘 | 前景时间 IoU 0.8822 → 0.9568；投影点并集 6094 → 6206 | 连续性有所改善；共同可见点上的前景诊断，不能当作语义准确率 |
| ScanNet0030 椅子 | 前景时间 IoU 0.9832 → 0.9848；投影点并集 8469 → 8472 | 前景差别很小；逐掩码分析更有信息 |
| ScanNet0030 椅子逐掩码 | 合并样/分裂样转变各 8 → 各 0；未匹配掩码观测 4 → 0 | frame40 图中独立图像产生 4 个掩码，视频 3 个，减少重复片段；未做 GT 实例评测 |
| Orbbec 卷盘文字提示 | 非空预测 1/16 → 4/16；投影点并集 243 → 378 | 相同提示词 `cable reel`，视频改善部分帧的持续性 |
| Orbbec 卷盘首帧正框视频 | 非空预测 7/16；投影点并集 425 | 属于人工辅助条件；后段卷盘已离开视野，非空比例不是召回率 |
| 3RScan 床 | 投影点并集 5257 → 2428 | 视频丢掉了原图中清楚可见的 frame0 床掩码，属于定性退化；即使时间 IoU 提高也不能接受 |

单帧图像与视频覆盖的有效前景对可能不同，特别是 3RScan。较高的时间 IoU 可能来自删除不稳定预测，因此必须同时检查覆盖、未匹配掩码与原图。视频 ID 在几何成功匹配的相邻掩码上保持一致，但模型自己的 ID 不是 GT，不能由此报告“追踪准确率 100%”。

## 蓝色特殊设备：现有模型能够给出掩码

同一张 Orbbec frame4811：

| 固定条件 | 输出 | 掩码像素数 |
|---|---|---:|
| `machine` | 3 个设备候选，包括蓝色设备、前景投影设备及灰色设备 | 各 44262、24943、68977 |
| `blue machine` | 单个蓝色设备掩码 | 38561 |
| 一个正框 | 单个蓝色设备掩码 | 41640 |
| 正框 + 负框 | 单个蓝色设备掩码 | 43488 |

原图检查显示，`blue machine` 已能分出蓝色设备主体，正框条件还包含更多上部部件。后三个掩码均位于冻结的正框范围内，与指定负框地面区域没有像素交集。这只是诊断性的边界检查，并不是像素 GT，也不能由像素变多推断更准确。

随后做了不调用模型的候选竞争回放：复用旧 31 条提示的原始缓存掩码，完全复现旧版 pre-family 语义结果，再加入上述保存的 `blue machine` 掩码作为临时类 35（仅表示提示描述）。原 RGB、深度哈希及掩码形状均完全匹配，PixelClaims 仍使用原来的 0.5 门槛与 0.1 类别差值。

结果：蓝色新掩码内的 38561 个像素，在旧候选竞争前后的有效结果以及 family 修复结果中全部未知；旧缓存中保留下来的 >=0.5 掩码没有覆盖其中任何一个像素。加入新掩码后，38561 个像素全部通过原来的竞争规则，区域外改变 0 像素。见 `blue_equipment/BLUE_COMPETITION.json`。

因此，这个特定帧的漏检已经定位到“旧提示集合未产生覆盖该物体的有效候选”，不是该区域被后面的类别差值规则压掉，也不是模型根本分不出它。这里并未查看低于模型输出门槛的所有 logits，不能宣称旧模型对所有类别完全无响应。后续三维投影、跨帧一致性和业务命名仍须单独验证；本轮没有更新生产分类表或完整三维地图。

卷盘的视觉正框同样产生了掩码，但部分黄色卷绕线缆未被完整纳入，说明一个框并不能保证完整物体边界。

## 建议

优先考虑：保留独立图像候选，借助视频跟踪改善跨帧重复；新增描述性/视觉候选应先进入未知名称的物体实例，再与已有类别命名分开处理。不要采用会无条件删除独立图像检测的纯视频替代方案。3RScan 稀疏、旋转、间断输入的失败应单独保留，后续若增加连续原始帧，需要明确报告增加的输入预算。

这些探针支持继续验证上述机制，但尚不支持把新的视频路线整体设为默认。
