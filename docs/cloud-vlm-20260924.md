# GPT-6 Sol 与 DeepSeek Flash 同输入实测 · 2026-09-24

在固定的 24 张裁图上，DeepSeek Flash 非思考模式、4 并发耗时 **6.60 s**，24 次请求全部成功并返回合格短名称。本地 Qwen3-VL-2B-NF4 的纯推理合计 **2.26 s**，含初始化 **7.10 s**。因此云端在这个小批次上接近本地冷启动时间，本地模型加载完成后的吞吐仍更高。

通过用户提供的 `https://api.huanling.icu/v1` 测试 GPT-6 Sol 六个请求档位，4 并发每组耗时 **157.61–248.54 s**，144 次请求共得到 118 个成功且格式合格的回答。当前这条中转链路的耗时与失败率不适合直接替换现有快速命名阶段；这些数值不能代表 OpenAI 官方接口。

原指定的 `gpt-6-luna` 在该接口返回 `404 model_not_found`，提示当前 key 分组没有支持它的账号；随后按用户确认改测 `gpt-6-sol`。生产 pipeline、默认模型及 Codex 全局配置均未修改。

查看 [结构化回执](cloud-vlm-20260924.json) 和 [逐图对照页](../profile_output/cloud-api/review.html)。对照页包含原始裁图、各组名称、请求状态与时间，图片保存在 Git 忽略的测量目录中。

## 同输入与计时范围

- 固定选取 24 张：ScanNet `scene0011_00`、`scene0030_00`、`scene0050_00` 各 4 张，Orbbec 352/1005 帧录制各 6 张。按各来源裁图序列均匀取索引，选择在云端响应前完成；包含同一物体的不同视角，不等于 24 个独立物体。
- 所有模型使用同一张原始裁图和现有短英文物体名称提示词。图片发送前、整轮后及本地对照页生成时核对 SHA256，没有重新运行 SAM3/SLAM 或改变裁图。各模型内部的图像预处理策略不同。
- 本地与 API 调用端均运行在原计算主机。Qwen 是已验证权重的本地 2B NF4；GPT 使用用户提供的中转 Responses API；DeepSeek 使用官方 Chat Completions API。GPT 请求发送 `store:false`，未验证中转服务内部的数据保留行为。
- API 每次请求只包含一张图，`original` 图像细节；“4 并发”指同时最多 4 个独立请求，不是把多张图片放进一个请求。输出 token 预算均为 4096，包含模型推理预算；提示词仍要求最多六个英文单词。
- 主对照连接/读取超时为 30/90 s，自动重试为 0。较早的串行 DeepSeek 对照使用 15/90 s，全部 HTTP 请求成功。前置连通性探测单独保留，不混入主表。
- API 总耗时包括编码/请求及失败等待；请求 p50/p95 同样包含失败请求。Qwen 的 2.26 s 是 24 次请求累计，7.10 s 另含导入、权重校验和模型加载。各组均为一次顺序执行，网络、服务负载、缓存和生成波动均可能影响结果，不能从这些单轮数据推导稳定的档位速度排名。

**档位回读异常：** GPT 的 18 条成功 `none` 请求全部回传 `reasoning.effort=medium`；此组不能称为已验证的无思考模式。其余五档的成功回执与请求档位一致。请求与响应模型字段均为 `gpt-6-sol`，但第三方回传的模型名不能独立证明底层权重身份。

GPT 主对照的 26 次失败包括连接中断、TLS 错误及读取超时。各组失败数不同，且没有交错随机化或重复整轮测试；high/xhigh 的整组耗时较短，不能直接归因于更高思考档位。有效结果在 24 张中覆盖的子集也不同，不能只在成功子集上比较准确率。

DeepSeek 串行 high 中有 1 次耗尽 4096-token 预算，3 次完成后仍输出长解释，现有解析器将它们标为格式不合格；4 并发 high 中有 1 次长解释，未出现截断。这是本次提示词与预算下的结果，不能推广为所有 high 配置的表现。

## 效果检查

本轮没有人工标注 GT，也没有计算新的类别准确率、3D IoU 或实例 AP。助手先对编号裁图记录了视觉备注，再查看批量模型输出；首张图的连通性响应已被看过。备注只是辅助检查，不能充当独立人工 GT。

几个可复核的例子：

- **ID 19：纸箱。** 本地输出 `house`，DeepSeek 非思考输出 `cardboard box`，属于有希望的修正。
- **ID 03：局部椅背。** 本地输出 `unknown`，DeepSeek 非思考输出 `brick`；unknown 减少并不能直接解释为精度提高。
- **ID 00：椅子。** GPT low 输出 `bag`，high 输出 `chair`，表明提高档位可能修正某些个例。
- **ID 16：纸箱。** 本地和 DeepSeek 非思考分别输出 `box` / `cardboard box`，GPT high 输出 `house`，说明更高档位仍有误判。
- **ID 12/18：绿幕前有三脚架及纸箱。** 模型在绿幕、幕布和支架之间选择不同目标。当前矩形裁图含多个物体，单纯更换模型并不能确定哪个物体才是待命名的目标。

DeepSeek 非思考两轮有 4/24 个名称变化，high 有 6/24 个变化，包含 `unknown` → `person`、`printer` → `projector` 等。两轮同时改变了并发和执行时间，不能把变化归因于并发本身。也不能将与本地输出不一致的比例称为准确率升降。

## 对当前 pipeline 的建议

1. **以速度为目标时，保留本地 Qwen 作为默认。** 本轮热模型处理 24 张约 2.26 s。DeepSeek 非思考可以作为少量请求或冷启动场景的候选，但尚未测完整长录制上的 API 端到端收益。
2. **优先试验 DeepSeek 非思考用于少量疑难对象复核。** 这次它的接口成功率和输出格式最稳定，个别名称有改善；需要再验证疑难样本筛选、错误的具体名称和多视角一致性，不能直接替换全量命名。
3. **当前 GPT 中转应先解决可用率及档位回读问题。** 在这条链路恢复稳定前，难以公平判断 GPT 档位对延迟和识别效果的作用。不能据本次结果否定其他接口的表现。
4. **进一步改善效果时，先检查目标证据。** 可试验目标 mask 提示或多视角输入，减少矩形裁图中的多物体歧义，再做冻结输入和最终地图/查询对照。这些策略本轮均未启用。
