# 验证范围与实验计划

当前可复核结果见 [2026-09-22 验收记录](acceptance-20260922.md)。以下条件用于解释已测范围，并约束后续默认策略提升。

## 已实现功能的验证边界

- 单元测试验证分数归属、冲突弃权、产物绑定、评价反例、几何查询、有效 RGB-D 超时及历史会话恢复。
- CPU 合成示例与 wheel smoke 验证安装和产物接口；不能作为 SLAM、SAM3 或 VLM 效果证据。
- 视角选取为 opt-in。质量与位姿差异只是工程代理量，不能把不同帧号或位姿差异当作统计独立证明。
- refinement 与离线 P2 保持独立开关，不能把在冻结几何上得到的增益直接解释为原始 RGB-D 端到端收益。
- GUI 重处理创建新 attempt，校验后复用完整 mapping/SAM3；未完成阶段、旧无seal记录、变化的输入/代码/运行环境均全量重跑。VLM、融合、命名与refinement不复用。

## 算法回归

保留三帧冲突反例：同一批点分别由 A/0.55、B/0.99、A/0.55 支持。显式 `track` 策略下 A 不能从 B 借用 0.99；显式 `abstain` 下投票冲突不会被对象共识填回。默认 `legacy + consensus` 保持原行为，其已知共享分数局限仍在；三场景配对结果未支持提升默认。无冲突的合法恢复应仍能通过。

对同一地图，冻结坐标、点序、SAM3 masks 和投影后比较多视角融合、guided recovery 与后续增强。记录：

1. 新增语义点与新增实例归属点各自的正确率；实例 ID 必须经过匹配，不能直接与 GT 数字相等比较。
2. 原未知区域恢复率及正确恢复率；报告原未知区域分母。
3. 原已有标签的变化量、正确变错误、错误变正确及保留比例。
4. GT 到预测的覆盖、对象漏检、实例匹配 precision/recall、碎裂与误合并。
5. 各阶段时间、模型调用数、峰值显存和全流程墙钟时间。

禁止仅用覆盖率或实例纯度判定提升。未知区域分母为零时应报告 null / 不适用，而不是恢复率 100%。不支持类别必须报告并说明排除范围。

## 同预算选帧对照

对每个序列分别运行固定预算的 stride、quality、quality-diverse。固定输入清单、模型版本、轨迹策略、种子、类别词表和预算；按场景汇总配对结果。记录每个策略实际选中帧、质量分、位姿分离及 fallback 帧。

至少包含原地停留、重复经过、遮挡、相似相邻物体及模糊转动情形。先在固定轨迹上隔离选帧收益，再独立运行原始 RGB-D 端到端对照。配置只在多个场景上同时满足恢复准确性、已有区域保护及资源预算要求后才考虑设为默认。

## 场景图与查询验收

先固定一个人工标注的小场景，准备至少 20 条类别、最近对象及空间关系查询。分别核对对象正确率、关系正确率、查询命中率和 unknown 比例。查询展示实际实例与支持帧；没有重力方向时，上方/支撑查询须拒绝推断。

增加漏掉目标、两个等距对象、实例错误拆分、类名与 VLM 名称冲突、无对应证据图等反例。空间关系暂为包围盒几何假设；真实接触/支撑需要额外的表面与法向分析。

## 真机与中断验收

分别模拟无 frameset、缺 RGB、缺 depth、同步超限，确认在配置的有效帧超时内失败且已有完整记录可封存。相机热启动与运行期超时应分别验证，避免对慢启动设备误判。

在采集、SAM3、VLM 和 refinement 阶段中断进程，重启 GUI 后打开历史会话并重新处理。确认新旧 attempt 不互相覆盖、当前状态不误报完成、最终产物清单哈希匹配。对 1 千、1 万、5 万行帧日志测量增量读取耗时及处理积压；CPU 改善应以实际测量报告，不预设 FPS 增益。
