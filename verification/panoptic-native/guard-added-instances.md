# 对补入表面的新实例编号进行复核

在主图与第二份 RGB-D 表面完成融合后，保留全部实测点及已关联的实例。对于只出现在新增点上的正实例编号，将其所属新增点的语义设为 ScanNet20 未知类 20，实例编号设为 0。在 PLY 中使用类别表的 21 号 unlabeled。

评分仍在完整有效真值顶点上进行。如果最近的实测点是未知类，参考类别仍计入评分，预测端不产生该点的物体实例。几何覆盖、双向最近点距离和坐标完全取决于保留的实测点。这一步的几何数值与原补点结果相同。

### 开发选择

在固定的 9 场官方训练扫描上，原补点方案得到 62.136% PQ、94 个真值命中和 86 个误检。保留新编号的坐标并标为未知后，PQ 为 62.236%，仍命中 94 个物体，误检减至 78 个，平均对称最近点距离保持 9.297 厘米。用同类主图几何重新关联部分点，在这些场景上得到相同的 PQ 与物体计数。直接删除全部新编号点得到 62.233% PQ，平均对称最近点距离为 9.305 厘米。依据预先登记的误检、命中、几何与 PQ 条件，选定标为未知这一种配置进入完整验证。

54 场 PQ 提高、87 场持平、1 场下降。配对 PQ 增量为 0.597 个百分点，以 134 个房间家族为单位重复抽样 4,000 次，95% 百分位区间为 0.359 至 0.862 个百分点。补点产生的新编号此前有 2 个真阳性和 245 个误检。复核移除了这 245 个误检，也失去 2 个真值匹配，分别是 `scene0412_00` 的其他家具和 `scene0607_00` 的冰箱。后者 PQ 下降 6.567 个百分点。逐场逐类检查表明，主图已有编号的命中和误检数均保持相同。两种读出均包含 79,043,367 个实测点。[每场新旧编号的匹配变化](guard-added-instances142.csv) · [逐类误检变化](guard-added-instances142-classes.csv) · [复评分数与封存依据](guard-added-instances142.json)

### 使用

输入目录来自 `tools/fuse_complementary_surfaces.py`，其中 `result.json` 记录原有点数与新增点数。命令读取同一份地图的类别和实例，核对散列后输出带标签 PLY、全景 NPZ、类别表和收据。

~~~bash
python tools/guard_added_instances.py --input "$FUSED_OUTPUT" --output "$GUARDED_OUTPUT"
~~~

联合模式使用 `--sensor`、`--primary-trajectory`、`--secondary-trajectory` 三项原生输入。在处理未知实例编号前，用未改动的语义和实例标签选择新增表面，再保留相应点的原始字段。几何策略为 `--surface-policy tight` 或 `relaxed`，默认使用 `tight`。上表报告只复核编号的固定输入实验。

发布函数在 9 场训练及 142 场验证中，对 20,235,450 个新增点的语义、实例和几何保留标志逐一核对，与冻结输出完全一致。对已有发布流程导出的 `scene0011_00` 和 `scene0063_00` 两份 PLY 再运行命令，场内分别有 19,213 和 23,089 个新增点标为未知，坐标、RGB 和其他点字段均与输入一致。[逐点和 PLY 等价收据](guard-added-instances-export.json)

~~~bash
python tools/guard_added_instances.py --input "$FUSED_OUTPUT" --output "$JOINT_OUTPUT" \
  --sensor "$SCAN_SENS" --primary-trajectory "$MAIN_TRAJECTORY" \
  --secondary-trajectory "$SECONDARY_TRAJECTORY" --surface-policy tight
~~~
